# proaudio-wire

PRO AUDIO WIRE — https://news.ainsonic.com (GitHub Pages)

## 구조

| 파일 | 역할 |
|---|---|
| `index.html` | 화면. 열릴 때 `news.json`을 읽어서 그림 (데이터를 HTML에 넣지 않음) |
| `news.json` | 소식 데이터 (배열, 위에 있을수록 먼저 표시 / 앞 6건이 "주요 6선") |
| `rss.xml`, `sitemap.xml`, `n/` | `scripts/build.py`가 `news.json`으로 자동 생성 |
| `scripts/build.py` | `news.json` 형식 검사 + 생성 파일 만들기 (`scripts/pages.py` 사용) |

## 자동 업데이트가 할 일 (토큰 절약 순서)

1. `python3 scripts/build.py --brief` — news.json(140KB+)을 통째로 읽지 말고 이 요약만 봅니다
   (가장 큰 id, 분류 비율, 최근 60일 소식의 원문 링크·제품명 → 중복 확인용).
2. 새 소식만 작은 파일(예: `/tmp/new.json`, 아래 형식의 배열, `id` 생략 가능)에 씁니다.
3. `python3 scripts/build.py --add /tmp/new.json` — id를 이어서 붙이고(국내 → 프로오디오 → 최신 순),
   이미 있는 원문 링크는 건너뛰고, 검사 통과 시에만 news.json 맨 앞에 넣은 뒤 아래 파일을 모두 다시 만듭니다.
   검사 실패면 new.json만 고쳐 다시 실행합니다(news.json은 그대로).
4. `git add -A` 후 커밋 (index.html의 미리보기 목록, `n/`, sitemap.xml도 함께 바뀜).

`build.py`가 만드는 파일 (손으로 고치지 않음):

| 파일 | 역할 |
|---|---|
| `rss.xml` | 최신 40건 피드. 각 항목 링크는 아래 소식 페이지 |
| `n/<id>.html` | 소식별 페이지. 구글이 제품명으로 찾을 수 있고, 메신저 공유 시 사진·요약 미리보기가 나옴 |
| `sitemap.xml` | 구글에 알려 줄 주소 목록 (`robots.txt`에 등록됨) |
| `index.html` | `PRERENDER` 표시 사이에 최신 30건을 미리 넣음 (검색엔진용, 화면은 JS가 다시 그림) |

내용이 같으면 파일도 바뀌지 않아서, 소식이 없는 날엔 커밋이 생기지 않습니다.
GitHub Actions(사진 채우기)도 같은 스크립트로 이 파일들을 다시 만들어 커밋합니다.

## news.json 항목 형식

```json
{
  "id": "news-100",
  "date": "2026-09-27",
  "company": "수입사/발표 주체 (예: 삼아프로사운드 (삼아사운드))",
  "brand": "브랜드 (예: Shure)",
  "productName": "제품명",
  "type": "신제품 | 업데이트 | 행사",
  "summary": "한두 문장 요약",
  "link": "https://원문",
  "evidence": "원문 인용 한 줄",
  "status": "published",
  "isDomestic": true,
  "category": "프로오디오 | 컨슈머오디오 | 레코딩소프트웨어 | 기타",
  "imageUrl": "https://... (선택)"
}
```

- `date`는 **게시일**입니다. 행사 개최일은 summary에 적어 주세요.
- `summary`는 독자(교회·공연장 음향 담당, AV 설치업체, 방송·스튜디오 엔지니어) 입장의 3~4문장, 공백 포함 180~260자(최대 280자):
  ① 누가 무엇을 발표했는지(제품 종류를 쉬운 한국어로) ② 핵심 특징·사양 2~3개(원문 수치 그대로)
  ③ 어디에 쓰는지·무엇이 달라졌는지(원문 근거가 있을 때만) ④ 가격·출시 시기·국내 수입사·행사 일시/장소/신청 방법(있을 때).
  원문에 없는 내용·과장 표현(혁신적인, 획기적인 등) 금지, "~했습니다/~입니다" 체.
- `status`를 `hidden`으로 바꾸면 사이트에서 숨겨집니다.

## 분류(category)와 목표 비율 — 60 : 10 : 20 : 10

| 분류 | 목표 | 들어가는 것 |
|---|---|---|
| 프로오디오 | 60% 이상 | 라이브·설치 음향(스피커, 앰프, 믹서, 무선마이크, DSP, Dante), 회의실·교육·교회 오디오, 방송·녹음실 하드웨어, 음향 설계 소프트웨어(EASE, ArrayCalc 등), 수입사 세미나 |
| 컨슈머오디오 | 10% 이하 | 헤드폰·이어폰, 개인·크리에이터용 USB 마이크·인터페이스, 홈오디오 |
| 레코딩소프트웨어 | 20% 이하 | DAW, 플러그인, 가상악기, 녹음·편집·측정 앱 |
| 기타 | 10% 이하 | 설치 영상 장비(프로젝터, 카메라, 영상 AV-over-IP), 신디사이저·기타 페달 등 악기, DJ, 업계 소식 |

- 비율은 최근 7일 게시 소식 기준. 프로오디오는 제한 없이 우선, 나머지는 프로오디오 양에 맞춘 상한 안에서만 추가
  (예: 프로오디오 6건 → 레코딩소프트웨어 최대 2건, 컨슈머 1건, 기타 1건).
- `python3 scripts/build.py`가 최근 7일·전체 비율을 출력합니다.
- 사이트 "주요 6선"은 프로오디오에서만 고릅니다.

## 사진 자동 채우기 (썸네일 항상 표시)

`news.json`이 바뀔 때와 매일 오전 8:30에 GitHub Actions(`fill-images.yml`)가 사진이 없는 소식을 채웁니다.

1. 원문의 대표 이미지(og:image)
2. 원문 사이트가 자동 접속을 막으면 페이지 읽기 서비스(r.jina.ai)로 우회
3. 대표 이미지가 없으면 본문 속 큰 사진
4. 그래도 없으면 "브랜드 + 제품명" 이미지 검색 — 브랜드명이 들어간 결과만 사용
   - Google 이미지 검색: SerpApi 키를 저장소 Secret `SERPAPI_KEY`로 등록하면 사용 (무료 월 250회, 한 번 실행에 최대 60회)
   - (Google 자체 검색 API는 신규 가입이 막혀 있고 2027-01-01 종료 예정이라 쓰지 않음)
   - 키가 없거나 실패하면 DuckDuckGo → Bing (GitHub 서버에서는 대부분 막힘)
5. 모두 실패하면 사이트는 브랜드명 디자인 카드를 보여주고, 3일 뒤 다시 시도(`imageTried`)

모든 이미지는 저장 전에 실제로 열리는지 확인합니다. 검색으로 찾은 사진은 `imageSource: "search"`로 표시되고
사이트에 작게 "관련 이미지"라고 나옵니다. 사진을 직접 넣으려면 `imageUrl`에 주소를 적으면 됩니다.

## 이번 주 동향 위젯 (stats.json, SEO용 매일 갱신)

`scripts/build.py`는 실행할 때마다 최근 7일/30일 창(window) 기준으로 브랜드 TOP5·분야 비율을
`stats.json`에 새로 계산해 저장합니다. `index.html`은 홈 상단에서 이 파일을 불러와
"📊 이번 주 프로오디오 동향" 위젯으로 보여줍니다.

`fill-images.yml`은 새 소식이 있든 없든 매일 오전 8:30(한국시간)에 무조건 실행되고 이때도
`build.py`가 다시 돌면서 `stats.json`을 새로 계산합니다. 최근 7일/30일 날짜 창이 매일 하루씩
밀리기 때문에, 새 소식이 0건인 날도 브랜드 순위·비율 숫자가 달라져 실제로 파일이 커밋되고
사이트 내용이 매일 갱신됩니다 — 검색엔진에 "매일 바뀌는 사이트"라는 신선도 신호를 주기 위함입니다.
내용 없이 날짜만 바꾸는 가짜 신선도가 아니라, 실제로 계산된 값이 바뀌는 방식입니다.
